# Architecture

## System shape

- **Backend:** FastAPI + Pydantic + synchronous SQLAlchemy, versioned under `/api/v1` with OpenAPI generated by FastAPI.
- **Database:** SQL Server with Alembic migrations. A global canonical `file_name_key` identifies each submission group. Atomic update/output allocation assigns per-group `arrival_seq`; optimistic `version` guards update/delete.
- **Frontend:** React, TypeScript strict mode, Vite, typed API module, and a reconnecting WebSocket client that re-fetches authoritative state after reconnect.
- **Images:** `ImageStorage` protocol with a local filesystem implementation. The database stores MIME, size, SHA-256, and opaque storage key, never base64.
- **Realtime:** versioned event envelopes and an in-process connection manager for the documented single API instance. HTTP responses and events are reconciled by result ID.
- **Export:** a UTF-8-BOM operational history CSV contains all received records, including soft-deleted rows. Separately, `ExportSelectionPolicy`, preview CSV adapters, deterministic `SubmissionZipBuilder`, and independent reopen/parse validation support internal previews. `OfficialFormatProvider` is fail-closed until verified configuration and tests exist.

## Data flow

1. `POST /api/v1/submissions` infers KIS/QA/TRAKE from `file_name`, validates the required `query_content` and type-specific body, and creates a global group on first sight; query ZIP import remains optional enrichment for group text.
2. Submission creation optionally decodes/stores an image, atomically allocates the immutable per-group arrival order, commits, then broadcasts metadata.
3. Update/delete enforce owner policy and expected version; `arrival_seq` never changes.
4. History export streams all submission rows as an operational CSV. Preview export remains a separate, unverified workflow; official export remains blocked.

## Trust boundaries

- ZIP names, image MIME, JSON body, query/answer/note, API keys, and WebSocket clients are untrusted.
- Secrets are environment-only. Logs contain request IDs and metadata, not API keys or base64.
- Official export is a correctness boundary: missing organizer rules produce a conflict, never guessed output.
